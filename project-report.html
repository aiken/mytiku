💾 数据流与存储详解

1. 本地提取后的存储结构（v2 — SQLite 版）

运行 extract_all.py 后，数据先写入 local.sqlite，再导出 SQL：

extract_output/
├── local.sqlite               ← 本地数据库（核心！支持查询/验证/清洗）
│   ├── papers 表               ← 2,942 份试卷元数据
│   ├── questions 表              ← 82,000+ 道题 + 5 维度标签
│   ├── tag_stats 表            ← 标签分布统计
│   └── extract_log 表          ← 提取日志（成功/失败/异常）
├── checkpoint.json              ← 断点记录（已处理文件列表）
├── failed_files.json          ← 解析失败的文件列表
├── manual_review.json         ← 需人工复核的文件
├── extract_stats.json         ← 标签分布统计报告
├── batch_sql/
│   ├── questions_part_001.sql   ← 从 SQLite 导出的 SQL（每批 5,000 条）
│   └── ...
└── images/
    ├── math/
    └── physics/
关键升级（v2）：数据先写入 SQLite 而非直接生成 SQL 文件。 好处：① 可查询验证 ② 可清洗修正标签 ③ 增量更新天然去重 ④ 标签分布统计一目了然。 最终用 db.export_to_sql() 导出为同样格式的 SQL 文件供上传。

2. SQL 文件内容格式

每个 questions_part_NNN.sql 包含两类 INSERT：

-- 1. 先插入 papers 表（去重，INSERT OR IGNORE）
INSERT OR IGNORE INTO papers (paper_id, title, subject, region, exam_type, year, 
  total_score, question_count, metadata) 
VALUES ('math_2019_北京_期末_xxx', '北京市xx区期末数学', 'math', '北京', '期末', 
  2019, 100, 28, '{"source": "..."}');

-- 2. 再插入 questions 表（每道题一条）
INSERT INTO questions (question_id, paper_id, question_number, q_type, position, 
  score, difficulty, content, options, answer, tags, images, estimated_time) 
VALUES ('q_math_2019_北京_期末_xxx_1', 'math_2019_北京_期末_xxx', '1', 
  'choice', 'basic', 3, 1, '题干文本...', 
  '[{"label":"A","text":"六边形"},...]', NULL, 
  '["多边形","几何"]', 
  '["images/math/xxx_q1_fig1.jpg"]', 3);
  ...
  （最多 5,000 条）
COMMIT;
参数化安全：所有字符串值经过 SQL 转义（单引号 → 双单引号）， 防止 SQL 注入。Workers 端同样使用 .bind() 参数化查询。

3. 上传到 Cloudflare 的方式

D1 数据库上传：通过 wrangler d1 execute CLI 命令执行 SQL 文件

# 单文件执行（内部自动使用事务）
wrangler d1 execute exam-bank-db --file=questions_part_001.sql --yes

# 特点：
# - 每文件一个事务，原子性保证
# - 超时 5 分钟，适合大批量写入
# - 免费层限额：50,000 次写入/天（≈ 50 个 5,000 条批次）

R2 图片上传：两种模式可选

# 模式 A：boto3（推荐，支持并发）
python upload_to_cf.py --images-dir ./extract_output/images/ 
  --r2-endpoint https://<account>.r2.cloudflarestorage.com
  --r2-access-key <key> --r2-secret-key <secret>

# 模式 B：wrangler（无需 boto3，但单线程）
python upload_to_cf.py --images-dir ./extract_output/images/ 
  --use-wrangler-r2 --r2-bucket exam-bank-assets
上传前检查：脚本会自动过滤 >50KB 的图片（跳过并记录日志）， 确保 R2 存储不超限。已上传的图片通过 upload_checkpoint.json 去重。

⚡ 上传效率优化方案
1. SQL 批量事务（已内置）
每 5,000 条 INSERT 包装为一个事务，而非逐条提交。 事务写入 ≈ 1 次计数，82,000 题仅需 17 个事务，远低于 D1 免费层 50 万/天限额。
--batch-size 5000 # 默认已是最优值
2. 图片并发上传（boto3 模式）
boto3 底层使用 HTTP 连接池，可配置 max_pool_connections 实现并发上传。 相比 wrangler 单线程，速度提升 5-10 倍。预计 3,000 张图片 10-20 分钟完成。
Config(max_pool_connections=20)
3. 断点续传（双重保障）
extract_all.py 每 100 文件保存 checkpoint.json，upload_to_cf.py 每成功一个文件 立即保存 upload_checkpoint.json。中断后重新运行自动跳过已完成部分，无需从头开始。
checkpoint.json + upload_checkpoint.json
4. 图片预压缩（提取阶段完成）
提取时即压缩：最大宽度 1200px → JPEG 75%质量 → 二次压缩 800px/60%。 单张 <50KB，总存储 <400MB。避免上传后再处理，节省带宽和时间。
--compress-quality 75 --max-image-width 1200
5. 分天执行策略（规避限额）
D1 免费层 50,000 写入/天 ≈ 50 个 5,000 条批次。建议每天执行 10-20 个 SQL 文件， 4-5 天完成全部上传。配合 cron 或手动分批，避免单日超限。
每天执行: python upload_to_cf.py --sql-dir ...
6. 解析版自动跳过（减少无效处理）
提取脚本自动识别文件名中的"解析版""答案版"等关键词并跳过。 2,942 份原卷版 vs 2,892 份解析版，节省近 50% 处理时间。
自动过滤: 解析版/答案版/解答版/参考答案
7. 多进程提取（CPU 并行）
extract_all.py 支持多进程并发处理 PDF/Word 文件。默认 4 个 worker， 可根据 CPU 核心数调整。2,942 份试卷预计 1-3 小时完成提取。
--max-workers 4 # 建议 = CPU 核心数
8. 本地缓存避免重复提取
checkpoint.json 记录已处理文件的绝对路径。再次运行时自动跳过， 适合增量更新（如新增试卷时只处理新文件）。
自动跳过 completed 列表中的文件
